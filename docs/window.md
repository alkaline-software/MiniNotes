# The window

About `crates/onyx-app/src/shell.rs`, `tabs.rs`, `ui_state.rs`, `main.rs`, `settings.rs`, and `crates/onyx-core/src/vault.rs`: the vault, a note's life, the tabs, the sidebar, the strip, the landing page, the sheets and menus, and what the window remembers.

## Rules

- **A note is written whole** (`vault::write`: a temp file beside it and a rename), and only when it is closed: when its tab closes (`close_tab`), before the vault closes or changes, when the window closes, at quit (`on_app_quit`, `save_all`), and at ⌘S (`save_now`, the note showing). Never while it is typed, and not when another tab shows: a keystroke marks the note dirty (`Shell::note_changed`, the dot on its tab) and that is all, so an hour of writing is one write to the disk and one upload for a sync, not one per pause. Never in place and never in part: a sync or another app reading the file sees the old note or the new one.
- **A note with changes is never replaced by the disk's text.** The watcher's reading goes into the editor only while `Note::dirty` is false (`disk_changed`), and then quietly (`Editor::replace_text_quietly`), keeping the caret and the history where the text still has them.
- **A note or a folder deleted goes to the system's trash** (`vault::trash`), never `remove_file`.
- **A rename refuses a taken name** and a name with a slash, and keeps a note's extension (`vault::rename`); the open note follows its new path, and so does a note inside a renamed folder.
- **The tree is read off the disk, never kept in step by hand.** After a change of Onyx's own, `reread_tree`; after another app's, the watcher.
- **The vault's folders of its own are not shown** (`.obsidian`, `.onyx`, `.trash`, `.git`, and anything that starts with a dot), and only notes (`.md`, `.markdown`) are listed.
- **Each tab has its own editor** (`Tab::editor`): the text, the caret, the scroll, the undo history and the dirty state stay with the tab while another shows, and a change to the faces, the size or the mode reaches every editor (`push_look`, `set_mode`). The editor's events name the tab they are for by its path, and a rename gives the editor a new listener under the new path. Tried and dropped: one editor handed each tab's text in turn, which lost the caret, the scroll and the history at every switch.
- **Everything the window remembers is written through `UiState`** (`save_ui`), never read from `Config`: the vault and the note are state, not settings.

## The vault

A vault is a folder. `vault::tree` reads it whole, folders first and then notes, each in the file manager's order (case folded, a number by its value, so Note 2 stands before Note 10), and the window keeps the result as `Vault::tree`. The folder is watched (`vault::watch`, the `notify` crate) from the moment it opens; the watcher's thread sends the paths that changed down a channel the window looks at every 300 ms (`watch_changes`), and a burst of them is one reading of the tree off the main thread (`disk_changed`). A note gone from the disk is closed.

Opening a vault (`open_vault`): the open note is written, the tree read, the folded folders of that vault put back from the window's state, the watcher started, and the vault put first among the recent ones (`UiState::remember_vault`, six kept). The system's folder picker is asked through `cx.prompt_for_paths` (`choose_vault`), from the landing page's pill, the sidebar's vault row, File, Open Vault… and ⌘⇧O.

A new vault (`start_new_vault`, from the landing page's primary pill, the sidebar's vault row and File, New Vault…) is a sheet: the name in a field, Notes to begin with, and where it goes as two rows. iCloud Drive puts it in Onyx's app library when the bundle is signed for one, else in an `Onyx` folder at iCloud Drive's root (`Shell::cloud_place`: `sys::icloud_container`, then `paths::icloud_drive`, `~/Library/Mobile Documents/com~apple~CloudDocs` on a Mac and iCloud for Windows' folder on Windows; the row is not shown where the machine has neither), so the system syncs it with no account of Onyx's own, as Obsidian's iCloud vaults are kept. On this computer puts it in a folder of the person's choice, the documents folder to begin with and the system's picker behind Choose…, for a vault that is also a git repository or anything else. ↩ or Create makes the folder (`vault::new_vault`, which keeps a folder of that name that is there already, so a vault synced from another machine is not refused, and refuses a file of that name) and opens it. What the app library takes is in `docs/platform.md`, iCloud Drive.

The watcher's changes are sifted before anything is read (`Shell::change_matters`): only a note, a folder, something gone that could have been one, and nothing under a dotted folder. A picture copied in, iCloud's bookkeeping and Obsidian's `.obsidian/workspace.json` cost no reading and no frame.

A wikilink names a note by its stem (`vault::resolve_link`): the link's own folder first, then the shortest path anywhere in the vault; a path with a slash is from the vault's root; a heading or an alias after `#` or `|` is dropped. A wikilink to no note makes the note at the vault's root, as Obsidian does (`open_wikilink`). A link that is a path opens the note it names when it is one of the vault's, else the file with the system's app; an address opens in the browser (`open_link`).

## A note's life

`open_note` reads the file, makes a tab for it with an editor of its own (`make_editor`: the look, the mode, the text, and the listener for its events), puts the tab at the end of its folder's pill (`sort_tabs`) and shows it (`show_tab`), with the keyboard in its editor. A note already open just shows. The editor says when its text changed (`EditorEvent::Changed`), and the window writes it as the rules say. A new note (`new_note_in`) is `Untitled.md` or the first free name after it, in the open note's folder, else the vault; it opens and its rename sheet comes up at once, so it gets its name while the person still means it. A new folder likewise. Both come from the sidebar's buttons, File, ⌘N and ⌘⇧N, or a folder's menu.

## The tabs

`tabs.rs` draws them; the shell holds them (`Shell::tabs`, in the row's order, and `shown`). As emaki has one tab per open session, Onyx has one per open note, and a folder's tabs stand together on one pill (`Tabs::group`, at every draw): the segmented control's track, with the folder's mark at its left end (its hover names the folder from the vault's root, or the vault) and the note showing on a raised plate. The pills are in the order their first tabs had, and a tab opened lands at the end of its folder's pill.

The plate is one element under a pill's tabs. It slides to another tab of the same pill, and between pills it fades out of one and into the other: a plate does not leave its track. It is placed by sum, never measured, since every width in the row is ours, and it reads the same clock the tabs' widths do (`Width::now`), so it keeps its tab while they move.

A tab is as wide as its name needs (`Tabs::sync`, at every draw): the title measured once in the tab's type at the showing tab's weight (`Tabs::fit`, by the theme's face, since the shell's render runs before any element's style is in force) plus the tab's edges, its close button and its outline, never under `TAB_LEAST` nor over `TAB_MAX`. Once the row has no room for every tab at its own width, the widest give way first (`Tabs::share`): one cap is set so the row is filled, every tab wider than it is cut to it, and the narrow keep their width; the cap goes no lower than `TAB_MIN`, and past that the tabs keep their widths and the row scrolls sideways, with the tab shown brought into view: centered while they fit, from the left once they do not. A new tab grows in from nothing while the others give way, a closed one's room is taken up the same way, and a new pill's track is let out with its tab, each over `TAB_ANIM`; the row's own width is measured as it is painted and used at the next draw. The window asks for a frame while anything in the row moves (`Tabs::moving`). Tried and dropped: the flex row sizing tabs to their titles and shrinking them itself, which drew a new tab at full width for a frame.

A tab is dragged along its pill and a pill along the row by its handle, the folder's mark, with the name on a ghost under the pointer and the one being moved drawn faint (`DragTab`, `DragPill`, `Ghost`; the row's `on_drag_move` hears both). The tab or pill stands after every neighbor whose middle the pointer has passed (`drag_tab_to`, `drag_pill_to`): going by the middle keeps two of different widths from changing places back and forth under a pointer that is still. The one tab of a pill takes the pill with it. Each neighbor that changed places slides to its new place from where it is now (`Shift`), the plate going with the showing tab, and the pill being moved is painted over the ones it passes (`deferred`). The row's new order goes to the shell (`Shell::reorder_tabs`), which keeps `Shell::tabs` in it and remembers it; `Tabs::group` keeps a drag's order since pills stand in the order their first tabs have. A press on a tab or a handle is the start of its drag, not the window's (`press_taken`, below).

⌘ held alone for half a second shows each of the first nine tabs its number on a small plate half over its lower edge, with an outline on every tab, and they go when the key is let go or another joins it, so a quick ⌘C never sees them (`Tabs::modifiers_changed`, from the shell's `on_modifiers_changed`; a release the window did not hear, after ⌘Tab away, is caught at the next draw). A probe shows them with `ONYX_GO=hints`.

A tab's close button is at its right; while the note has changes not written, a dot in the accent stands in its place until the pointer is over it. ⌘W closes the tab showing and the next one shows in its place, then with no tab left the vault's page, and then the window (`close_nearest`; `main.rs` closes any other window, the settings, on a ⌘W no view claimed). ⇧⌘W is the window straight away. ⌘⇧T opens the tab closed last again, and at each further press the one closed before it, passing over a note gone since or open again (`closed_tabs`, `reopen_tab`). ⌘1 to ⌘9 go to that tab in the row's order, or the last when there are fewer (`go_tab`). The open tabs, their order and the one showing are remembered (`UiState::tabs`, `note`) and open again at launch.

## The sidebar

`render_sidebar`. The wordmark, the vault's row (its list: Open Vault…, Reveal in Finder, Close Vault), the two buttons, the tree, the foot. The tree is `render_tree`: the vault's tree flattened into pieces (`tree_pieces`), a row for each entry and an open folder's children after its row, and only the pieces in view are drawn (`TREE_OVER` rows beyond the list's box at either end); the rows above and below stand as one empty box each, of their height, so the list keeps its length and the scroll its place. Every row is `TREE_ROW_H` tall, so where each stands is a sum and nothing is measured, and a vault of a thousand notes costs the frame no more than the rows in view. The list's box and offset are read off `side_scroll` as last painted; before the first paint, `TREE_FIRST` of the tree is drawn from its top. A folder's children on their way in or out are one piece, a fold (`Piece::Fold`): a box that runs up to their height and back, the content fading with it, keyed on the folder's path so each change plays once and the first sight plays nothing (`Motion::presence`, with `Motion::progress` for how far the box has run, so what stands below it is placed right while it moves). The folded set is `Vault::folded`, remembered per vault. A row (`render_row`): the chevron (a folder), Catppuccin's icon, the name, on a plate while it is the open note. Every row and every fold is `flex_shrink_0`: a scroll box's children shrink to fit it otherwise, and a tree taller than the sidebar drew its folders empty and its rows squeezed. Tried and dropped: a canvas measuring each fold's children, and every row of the vault drawn at every frame, which cost a frame some 16 µs a note, visible or not. A right click opens the row's menu (`entry_menu`): a note's is Open, Reveal, Copy Path, Rename…, Move to Trash; a folder's is New Note, New Folder, Reveal, Rename…, Move to Trash.

## The strip and the modes

The strip is the card's top: the sidebar's button at the left over the traffic lights, drawn once so it does not move with the sidebar; the tabs in the middle, clear of both ends by `STRIP_GAP`; at the right the modes as a segmented control of icons alone (a pencil, a file of code and an open book, each named with its key on hover: `Motion::segmented` with `icons`) and the gear. The mode is the editor's (`Editor::set_mode`) and is remembered (`UiState::mode`), so a note opens as the last one was shown. ⌥1, ⌥2 and ⌥3 are Edit, Source and Read, ⌘E goes to Read and back, and the View menu names all three. The ⌥ chords reach the editor only because its input handler puts the bindings before an input method (`docs/editor.md`, Rules).

The strip is the window's to drag by (`drag_region`): a press on it moves the window once the pointer moves with the button down, unless a tab, a pill's handle or a button took the press first (`press_taken`, set by a child's mouse-down listener, which runs before the strip's), and a double click is the title bar's.

## The landing page

With no vault: the name in the name's face and the accent, one sentence, two pills (New Vault… as the primary, Open Vault…), and the recent vaults on a card. With a vault and no note: one line and a New Note pill. Each page fades and rises in (`page_in`) when it arrives.

## The sheets

`render_sheet` draws one: a card over a scrim with a title, what it asks, its pills and a line of keys; Esc or a press off the card lets it go, and the card occludes, so a press in it let go outside does not close it. Each sheet's name is in the toolkit's `Input` (`rename_input`, `vault_input`, each made with the window, since an input watches the window it was made in), and ↩ keeps it through the input's `PressEnter`. The rename sheet (`render_rename`) and the new-vault sheet (`render_new_vault`) are the two; one is up at a time. After a sheet the keyboard goes back to the editor when a note is open, else to the window.

## The settings

`settings.rs`, the studio's window: a rail of three sections, the page at the right, drawn from the main view's state so a change shows in both windows. Appearance has the appearance and the accent, and the language at the right of its title. Text is two pages, chosen at the right of its title (`settings_page`): Fonts, the note's face as serifs over sans serifs, code's face and the Chinese face, each on a tile drawn in itself (`fonts_rows`, emaki's Text page), with a field under each card for a font installed on the Mac (`font_inputs`, made with the settings window and listened to for a change; a tile chosen clears the field over it); and Size (`size_rows`), a preset for both places at once (Small, Medium, Large, Custom: `EditorConfig::text_size`, `TextSizes`) with each place's size under it on a stepper, which only Custom moves, and a button back to Medium's beside a size that left it, then Readable line length. Custom's own sizes are kept while a preset is chosen (`EditorConfig::sizes`). About has the title card, Alkaline Software presents with the studio linked, and the updates. A change to a face or a size reaches every editor through `Shell::push_look`.

## What the window remembers

`ui_state.rs`, `~/.onyx/state/ui.json`: the bounds (from `window_bounds()`, never `bounds()`), whether the sidebar is open, the settings' section, the vault, the note, the mode, the recent vaults, the folded folders. Written when any of it changes (the bounds at most every two seconds), at quit, and when the close button closes the window. The writing is a thread's own (`UiState::save_later`, `Shell::save_ui`), the saves in the order asked: `write_atomic` flushes the file to the disk, some 5 ms on an SSD, and a frame is not to wait on that for a tab moved mid-drag or a folder folded. What was last asked is kept and is what `UiState::load` gives, so a state read, changed and written again never misses one still on its way. The window's close (`Shell::save_ui_now`) and the app's quit (`UiState::flush`) wait for the disk, since on Windows and Linux the close ends the app.

## Probing

`ONYX_VAULT=<folder>` opens that vault instead of the remembered one, `ONYX_NOTE=<file>` that note; `ONYX_GO` steps: `note` (the first note), `notes` (the first three, as tabs), `close` (⌘W), `sidebar`, `menu` (the first note's menu), `rename` (its rename sheet), `vault` (the new-vault sheet), `live`, `source`, `reading`, `end`. With `HOME` pointed at a scratch folder the sheet finds no iCloud Drive and makes the vault in that folder's `Documents`, so a probe can press ↩ without touching the person's iCloud. `ONYX_SETTINGS=text` opens the settings on that section (`docs/probing.md`).
