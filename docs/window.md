# The window

About `crates/onyx-app/src/shell.rs`, `tabs.rs`, `ui_state.rs`, `main.rs`, `settings.rs`, and `crates/onyx-core/src/vault.rs`: the vault, a note's life, the tabs, the sidebar, the strip, the landing page, the sheets and menus, and what the window remembers.

## Rules

- **A note is written whole** (`vault::write`: a temp file beside it and a rename), and only when it is closed: when its tab closes (`close_tab`), before the vault closes or changes, when the window closes, at quit (`on_app_quit`, `save_all`), and at ⌘S (`save_now`, the note showing). Never while it is typed, and not when another tab shows: a keystroke marks the note dirty (`Shell::note_changed`, the dot on its tab) and that is all, so an hour of writing is one write to the disk and one upload for a sync, not one per pause. Never in place and never in part: a sync or another app reading the file sees the old note or the new one.
- **A note with changes is never replaced by the disk's text.** The watcher's reading goes into the editor only while `Note::dirty` is false (`disk_changed`), and then quietly (`Editor::replace_text_quietly`), keeping the caret and the history where the text still has them.
- **A note or a folder deleted goes to the system's trash** (`vault::trash`), never `remove_file`.
- **A rename refuses a taken name** and a name with a slash, and keeps a note's extension (`vault::rename`); the open note follows its new path, and so does a note inside a renamed folder, and so does everything else that knows a note by its path (`Shell::rename_entry`: Wide, the last note shown, the closed tabs). Anything new kept by path goes there too. What must survive a rename is keyed by the note, not the path: a page's fade in is keyed by its editor (`render_page`), or a rename replays it.
- **The tree is read off the disk, never kept in step by hand.** After a change of Onyx's own, `reread_tree`; after another app's, the watcher.
- **The vault's folders of its own are not shown** (`.obsidian`, `.onyx`, `.trash`, `.git`, and anything that starts with a dot), and only notes (`.md`, `.markdown`) are listed.
- **Each tab has its own editor** (`Tab::editor`): the text, the caret, the scroll, the undo history and the dirty state stay with the tab while another shows, and a change to the faces, the size or the mode reaches every editor (`push_look`, `set_mode`). The editor's events name the tab they are for by its path, and a rename gives the editor a new listener under the new path. Tried and dropped: one editor handed each tab's text in turn, which lost the caret, the scroll and the history at every switch.
- **A size the next frame depends on is figured as the frame is built, never measured off the last one.** While a frame is drawn, gpui's `cx.notify` asks for no other frame (`invalidate_view` marks the window dirty only outside a draw), so what a canvas reads in prepaint waits for whatever draws next. With the pointer at rest after a window was resized by a key, nothing did: the tabs stayed at the old row's widths and place. The row's width and the page's come from the window's and the sidebar's (`Shell::render`).
- **Everything the window remembers is written through `UiState`** (`save_ui`), never read from `Config`: the vault and the note are state, not settings.

## The vault

A vault is a folder. `vault::tree` reads it whole, folders first and then notes, each in the file manager's order (case folded, a number by its value, so Note 2 stands before Note 10), and the window keeps the result as `Vault::tree`. The folder is watched (`vault::watch`, the `notify` crate) from the moment it opens; the watcher's thread sends the paths that changed down a channel the window looks at every 300 ms (`watch_changes`), and a burst of them is one reading of the tree off the main thread (`disk_changed`). A note gone from the disk is closed.

Opening a vault (`open_vault`): the open note is written, the tree read, the folded folders of that vault put back from the window's state, the watcher started, and the vault put first among the recent ones (`UiState::remember_vault`, six kept). The system's folder picker is asked through `cx.prompt_for_paths` (`choose_vault`), from the landing page's pill, the sidebar's vault row, File, Open Vault… and ⌘⇧O.

A new vault (`start_new_vault`, from the landing page's primary pill, the sidebar's vault row and File, New Vault…) is a sheet: the name in a field, Notes to begin with, and where it goes as two rows. iCloud Drive puts it in Onyx's app library when the bundle is signed for one, else in an `Onyx` folder at iCloud Drive's root (`Shell::cloud_place`: `sys::icloud_container`, then `paths::icloud_drive`, `~/Library/Mobile Documents/com~apple~CloudDocs` on a Mac and iCloud for Windows' folder on Windows; the row is not shown where the machine has neither), so the system syncs it with no account of Onyx's own, as Obsidian's iCloud vaults are kept. On this computer puts it in a folder of the person's choice, the documents folder to begin with and the system's picker behind Choose…, for a vault that is also a git repository or anything else. ↩ or Create makes the folder (`vault::new_vault`, which keeps a folder of that name that is there already, so a vault synced from another machine is not refused, and refuses a file of that name) and opens it. What the app library takes is in `docs/platform.md`, iCloud Drive.

The watcher's changes are sifted before anything is read (`Shell::change_matters`): only a note, a folder, something gone that could have been one, and nothing under a dotted folder. A picture copied in, iCloud's bookkeeping and Obsidian's `.obsidian/workspace.json` cost no reading and no frame.

A wikilink names a note by its stem (`vault::resolve_link`): the link's own folder first, then the shortest path anywhere in the vault; a path with a slash is from the vault's root; a heading or an alias after `#` or `|` is dropped. A wikilink to no note makes the note at the vault's root, as Obsidian does (`open_wikilink`). A link that is a path opens the note it names when it is one of the vault's, else the file with the system's app; an address opens in the browser (`open_link`).

## A note's life

`open_note` reads the file, makes a tab for it with an editor of its own (`make_editor`: the look, the mode, the text, and the listener for its events), puts the tab at the end of its folder's pill (`sort_tabs`) and shows it (`show_tab`), with the keyboard in its editor. A note already open just shows. The editor says when its text changed (`EditorEvent::Changed`), and the window writes it as the rules say. A new note (`new_note_in`) is `Untitled.md` or the first free name after it, in the open note's folder, else the vault; it opens and its rename sheet comes up at once, so it gets its name while the person still means it. A new folder likewise. Both come from the sidebar's buttons, File, ⌘N and ⌘⇧N, or a folder's menu.

## The tabs

`tabs.rs` draws them; the shell holds them (`Shell::tabs`, in the row's order, and `shown`). As emaki has one tab per open session, Onyx has one per open note, and a folder's tabs stand together on one pill (`Tabs::group`, at every draw): the segmented control's track, with the folder's mark at its left end (its hover names the folder from the vault's root, or the vault) and the note showing on a raised plate. The pills are in the order their first tabs had, and a tab opened lands at the end of its folder's pill.

The plate is one element under a pill's tabs. It slides to another tab of the same pill, and between pills it fades out of one and into the other: a plate does not leave its track. It is placed by sum, never measured, since every width in the row is ours, and it reads the same clock the tabs' widths do (`Width::now`), so it keeps its tab while they move.

A tab is as wide as its name needs (`Tabs::sync`, at every draw): the title measured once in the tab's type at the showing tab's weight (`Tabs::fit`, by the theme's face, since the shell's render runs before any element's style is in force) plus the tab's edges, its close button and its outline, never under `TAB_LEAST`, a comfortable tab for a short name, nor over `TAB_MAX`. Once the row has no room for every tab at its own width, the widest give way first (`Tabs::share`): one cap is set so the row is filled, every tab wider than it is cut to it, and the narrow keep their width; the cap goes no lower than `TAB_MIN`, and past that the tabs keep their widths and the row scrolls sideways, with the tab shown brought into view; the row is centered while the tabs and the plus fit, and runs from the left once they do not, which is a padding of ours (`Tabs::lead`) and not the row's own centering, so it can move. A new tab grows in from nothing while the others give way, a closed one's room is taken up the same way, and a new pill's track is let out with its tab, each over `TAB_ANIM`. Whatever changes the row's room, a window resized or the sidebar moved, every width, the lead and the scroll that brings the tab shown into view head for their new values from where they stand (`Width::head`, `TAB_ANIM`), so the tabs glide; asked again at every frame of a drag, they follow it and catch up when it stops. The window asks for a frame while anything in the row moves (`Tabs::moving`). A width's animation element keeps its id through all of this: it is there to read the clock, and a new id at each step would lose a press on a moving tab. Tried and dropped: the flex row sizing tabs to their titles and shrinking them itself, which drew a new tab at full width for a frame.

A tab is dragged along its pill and a pill along the row by its handle, the folder's mark, with the name on a ghost under the pointer and the one being moved drawn faint (`DragTab`, `DragPill`, `Ghost`; the row's `on_drag_move` hears both). The tab or pill stands after every neighbor whose middle the pointer has passed (`drag_tab_to`, `drag_pill_to`): going by the middle keeps two of different widths from changing places back and forth under a pointer that is still. The one tab of a pill takes the pill with it. Each neighbor that changed places slides to its new place from where it is now (`Shift`), the plate going with the showing tab, and the pill being moved is painted over the ones it passes (`deferred`). The row's new order goes to the shell (`Shell::reorder_tabs`), which keeps `Shell::tabs` in it and remembers it; `Tabs::group` keeps a drag's order since pills stand in the order their first tabs have. A press on a tab or a handle is the start of its drag, not the window's (`press_taken`, below).

⌘ held alone for half a second shows each of the first nine tabs its number on a small plate half over its lower edge, with an outline on every tab, and they go when the key is let go or another joins it, so a quick ⌘C never sees them (`Tabs::modifiers_changed`, from the shell's `on_modifiers_changed`; a release the window did not hear, after ⌘Tab away, is caught at the next draw). A probe shows them with `ONYX_GO=hints`.

A tab's close button is at its right; while the note has changes not written, a dot in the accent stands in its place until the pointer is over it. ⌘W closes the tab showing and the next one shows in its place, then with no tab left the vault's page; on the vault's page with tabs still open it gives way to the tab shown last (`last_shown`, kept by `show_home`), or the row's last, and only on the page with no tab open does it close the window (`close_nearest`; `main.rs` closes any other window, the settings, on a ⌘W no view claimed). ⇧⌘W is the window straight away. ⌘⇧T opens the tab closed last again, and at each further press the one closed before it, passing over a note gone since or open again (`closed_tabs`, `reopen_tab`). ⌘1 to ⌘9 go to that tab in the row's order, or the last when there are fewer (`go_tab`). The open tabs, their order and the one showing are remembered (`UiState::tabs`, `note`) and open again at launch.

## The sidebar

`render_sidebar`, after emaki's, on the frame with the frame's inks whatever the appearance (`frame_theme`): the title row with the app's icon and the wordmark at its right, the window's to drag by; the New Note row with its accent disc and the New Folder row under it, each with its key at the right; the notes card, with the vault's name on its title strip (its press opens the vault's list: New Vault…, Open Vault…, Reveal in Finder, Close Vault) and the tree in it (`render_notes_card`); and the foot with the person's picture (`avatar`: the picture chosen in Settings, Appearance, cut square and kept at 512 and at each size it is drawn at, or their initial on the accent), their name in the wordmark's face (`name_of`: the settings' own, or the account's first name) and the settings' gear. The sidebar's button and the search's stand beside the traffic lights, drawn once over the window (`render_strip`), so they do not move with the sidebar's content.

**Folded, the sidebar is a rail** (`render_rail`), as emaki's: a column `RAIL_W` wide at the window's left with the traffic lights stacked at its head on a Mac (`sys::fold_lights`, called at every draw with how far the sidebar is, which moves the system's buttons between gpui's row and the column and puts them back whenever gpui moves them), then the sidebar's button and the search's a size larger, a rule, the New Note disc, the notes card's button, and at the foot the app's icon and the person's picture. The notes card's button flies the card out beside the rail over the page (`render_rail_fly`), for a note picked without the sidebar; a press beside it, Esc or a note shown lets it go. The sidebar's column grows from nothing to its width on one eased clock (`side_t`, `SLIDE`) while the sidebar itself stays put and fades in over the last part of the way; the rail fades out over the first part; the two buttons and the lights slide between their two places; and the card's left edge waits at the rail's until the column is past it. Nothing slides sideways but what the two states share.

**Its width is the person's** (`sidebar_w`, kept, `SIDEBAR_W` to begin with), after emaki's: a strip `SIDEBAR_GRIP` wide over the sidebar's edge (`render_side_grip`) lights a line under the pointer and takes a drag, which sets the width to where the pointer is between `SIDEBAR_MIN`, room for the lights, the two buttons and the name, and `SIDEBAR_MAX`. Left of `SIDEBAR_FOLD_AT` the sidebar folds to the rail, and brought back out in the same drag it opens again. The strip stays on the rail's edge while the sidebar is folded, so a drag from there past `SIDEBAR_FOLD_AT` brings it out, and a double click opens it at the fitted width. A held edge is heard in the capture phase, so it follows the pointer wherever it goes and nothing under it hears the move. A double click goes to the width at which the tree's rows in view are not cut (`sidebar_fit`), from `SIDEBAR_MIN` to `SIDEBAR_FIT_MAX`, so one long name does not ask for the most, over `SLIDE`. The notes card flown out from the rail is the same width.

The tree is `render_tree`: the vault's tree flattened into pieces (`tree_pieces`), a row for each entry and an open folder's children after its row, and only the pieces in view are drawn (`TREE_OVER` rows beyond the list's box at either end); the rows above and below stand as one empty box each, of their height, so the list keeps its length and the scroll its place. Every row is `TREE_ROW_H` tall, so where each stands is a sum and nothing is measured, and a vault of a thousand notes costs the frame no more than the rows in view. The list's box and offset are read off `side_scroll` as last painted; before the first paint, `TREE_FIRST` of the tree is drawn from its top. A folder's children on their way in or out are one piece, a fold (`Piece::Fold`): a box that runs up to their height and back, the content fading with it, keyed on the folder's path so each change plays once and the first sight plays nothing (`Motion::presence`, with `Motion::progress` for how far the box has run, so what stands below it is placed right while it moves). The folded set is `Vault::folded`, remembered per vault. A row (`render_row`): the chevron (a folder), Catppuccin's icon, the name, ended with an ellipsis where it does not fit, on a plate while it is the open note. Every row and every fold is `flex_shrink_0`: a scroll box's children shrink to fit it otherwise, and a tree taller than the sidebar drew its folders empty and its rows squeezed. Tried and dropped: a canvas measuring each fold's children, and every row of the vault drawn at every frame, which cost a frame some 16 µs a note, visible or not. A right click opens the row's menu (`entry_menu`): a note's is Open, Reveal, Copy Path, Rename…, Move to Trash; a folder's is New Note, New Folder, Reveal, Rename…, Move to Trash.

## The strip, the path bar and the modes

The strip is the card's top: the tabs in the middle, clear of both ends by `STRIP_GAP`, and after the last of them a square on a track of its own with a plus on it (`PLUS_W`, drawn with the row), raised while the vault's page shows, whose press shows the page and leaves every tab open (`show_home`); the row keeps its room in the width it shares out, and with no tab open there is no row and no plus, since the page is showing anyway. Tried and dropped: the tabs from the left with a home tab before them, which left the strip lopsided. The strip is the window's to drag by (`drag_region`): a press on it moves the window once the pointer moves with the button down, unless a tab, a pill's handle or a button took the press first (`press_taken`, set by a child's mouse-down listener, which runs before the strip's), and a double click is the title bar's.

Under the strip the card turns to the page's tint (`page_ground`: the card's color under the muted shade at 0.3), one ground for the path bar, the find bar and the page with no line between them, so the sheet's edge is the one line below the tabs. The card paints no ground of its own: the strip rounds its top two corners and the tint its bottom two, at `CARD_R`, because `overflow_hidden` clips to a square and whatever paints square into a corner shows there. On the tint runs the path bar (`render_path_bar`), after emaki's path line, a row of `PATH_BAR_H` with no ground or line of its own and the path alone in its middle: the note's name with its folder before it from the vault's name, in code's face, or the vault's own place while its page shows (`sys::short_path`: from `iCloud Drive` for a vault there, else from `~`), a chip whose press reveals it in the file manager. Tried and dropped: a band for the path with a hairline above and below, which with the sheet's edge put four lines in the top 120 of the card; the modes and widths on this bar, which said they belonged to the note showing.

The ends of the tabs' row (`render_strip_ends`) hold how notes are shown and how wide, the app's own and not a note's: only the person changes them, nothing resets them, and a first launch is Edit and Narrow (`UiState::mode`, `UiState::page_width`; the second is not named `wide`, which earlier builds kept as a list of notes, and a file with that list must go on reading). Each is a capsule as tall and as round as the tabs' pill, one hairline with its choice in it and no plate, at every width of the window, since the plate says which of several is chosen and at rest there is one (`render_strip_square`): at the left the mode, in a color of its own, the pencil in amber (the theme's warning), the source in blue (info), the book in green (success); at the right the width, in the accent. They show only while a note shows, fading as they come and go, and both ends keep their width with or without them, so the tabs keep one center line. A press opens a capsule in place (`render_strip_fly`): it widens along the row to hold the group of three (`Motion::segmented_tinted`), the modes to the right and the widths to the left, the chosen one sliding from where it stood to its own place as its plate comes, over `SLIDE`, and a choice, a press anywhere else or Esc folds it back, from wherever it stands (`strip_fly_open`). The open group lies over the tabs and moves nothing, solid, with its line and a small shadow that comes as it opens, so a tab under it passes behind a clean edge. Tried and dropped: the group always open, wider than a narrow window could spare; the three on a card under the square, which read as a menu and not as the same control opened; the tabs moving aside as it opens, which made every press move the whole row; an edge that faded over the tabs, which looked uneasy; and a plate inside the line at rest, two layers for one button. ⌃1, ⌃2 and ⌃3 are Edit, Source and Read, ⌘E goes to Read and back, ⌥1, ⌥2 and ⌥3 are Narrow, Middle and Wide, and the View menu names all six. Off a Mac the modes are ctrl-alt with a digit, since ctrl with one picks a tab there. The chords reach the editor only because its input handler puts the bindings before an input method (`docs/editor.md`, Rules). On a Mac ⌃ with a digit can also be Mission Control's Switch to Desktop, set in the system's keyboard shortcuts; where it is on the system takes the key first and Onyx never hears it. A change of mode leaves the keyboard where it is: a caret placed stays placed, and a note left by a click in the margin keeps reading whole (`docs/editor.md`).

**The sheet and its width.** A note is a sheet on the page (`render_note`): a column of the card's ground with a hairline round it on the page's tint, which runs up under the path bar to the tabs' row, with `SHEET_MARGIN` of the tint showing round it, so the words' room and the margins read apart; the words stand `SHEET_GUTTER` in from the sheet's edge. There are three widths (`PageWidth`, `sheet_width`): Narrow, `NARROW_W`, a comfortable line of reading; Wide, to the page's edges less the margin, with more room inside for the words; and Middle, halfway between the two as far as `MIDDLE_MOST`. Middle is figured from the page and not fixed so it always stands between the other two, and it stops so a big monitor does not stretch it toward Wide. A page no wider than Narrow has room for one width, and all three are it. A change eases over `SLIDE` on the window's clock, along a level from Narrow (0) to Wide (2) (`width_level`, from wherever it stands, so a second press turns it), the sheet's width and its gutter moving together and the words wrapping as they go; the page's width is figured as each frame is built, from the window's and the sidebar's (`page_w`), never measured from the frame before, which left Wide a frame behind a window being resized and then a moment more until the next draw. The find bar is the sheet's width.

**The note's name** stands over its words, a soft line under it (the border at 0.7), and it is the file's name, so typing there renames the file (`make_title`, `keep_title_at`). It is a `Textarea` of the tab's own, as the editor is, set `flush` so it lines up with the words, and it wraps as long as `TITLE_ROWS`. ↩ keeps the name and goes to the words, and so does the keyboard leaving by any other way; closing the tab keeps it first (`close_tab`). Esc puts the file's name back and goes to the words (`drop_title`). A name that cannot be used (a slash, a name taken, nothing) puts the file's name back, with a notice where there is something to say. A line break, from ⇧↩ or a paste, is a space. In Read mode and on a locked note it is plain words drawn alike, so a change of mode moves nothing. gpui tells a field it lost the keyboard after the frame that moved it, when another note may be showing, so the event finds its tab by the field (`keep_title`), never by the note shown. A new note's name still comes up in the rename sheet.

**A scroller's edges** (`edge_fade`, on the note, the notes card and the landing page) fade into the ground beneath while there is more beyond, whole with `FADE_ROOM` left to scroll and none at the end (`fade_strength`). What is under a fade counts as out of sight, as if a hard edge stood there, and the fade only lets the words show: the zone takes no press and no hover (a hitbox that blocks all but the wheel, so a scroll over it still works, and the scrollbar is drawn after it and stays on top), and its height follows the fade's strength, so what reads whole is live. It holds at both ends alike. A fade standing in a rounded card rounds its own foot to that card's radius (`corner`), or it paints the corner square. `FADE_H` is the editor's `SCROLL_MARGIN`, which keeps the caret out of it (`docs/editor.md`); change the two together. The fade is a canvas set after its scroller and reads the handle as it is placed: a scroller's length is known only once it is laid out, so read in `render` it is a frame late and missing from the first frame of a long note.

**The find bar** (`render_find_bar`, ⌘F, Find… in the Edit menu) slides in under the path bar over the note: the phrase in a field, how many matches and which, and the way to the next (↩, ⌘G) and the one before (⇧↩, ⌘⇧G), round the ends; Esc, the close button or ⌘F in the field closes it. The editor finds every place the phrase is (`Editor::set_find`, with `search::find_all`, found again after each edit), washes them all and stands on one, which is the selection, scrolled into view; the one stood on begins at the first match at or after the caret.

**The search** (`render_search`, ⌘K, Search… in the View menu, the magnifier beside the traffic lights) is a palette over the whole window, as emaki's: a field, and under it the notes the phrase is in, the ones named by it first and then by how often it is in them, each with its folder, its count and its first lines with the phrase marked (`onyx_core::search`, every note read and looked through off the main thread at each keystroke, the newest search winning, since a vault keeps no index). ↩ opens the first, a press any one, with the phrase in the note's find bar; Esc or a press beside the card closes it.


## The landing page

With no vault: the name in the name's face and the accent, one sentence, two pills (New Vault… as the primary, Open Vault…), and the recent vaults on a card. With a vault and no note (`render_no_note`): emaki's home page with Obsidian's new tab on it. The drawing (`home_figure`) is the icon's own picture, after emaki's handscroll: a notebook on a tile of onyx, a thin cut slab seen from above and a little to the left with its thickness at the front and a vein of the band's teal across its top, and a pen by it. A picture is painted in one color, so the drawing is layers of one color each, in the icon's own colors whatever the accent or the appearance: the tile's base, sides, top, vein, glint and shadow, the notebook's pages, cover, lines and bright line; the pen is one color, the lines' gray in the light appearance and the pages' warm white in the dark (the window's foreground was tried and was too hard beside the picture), so it shows on either ground, with its nib's slit in the paper's and an edge in the ground's color under it, so it stands off the tile and the lines it crosses. The tile's and the pen's layers are pictures in `icons/home/` (a face's corners are rounded by a stroke of its own color); the notebook's five are made as text at each draw with its tilt written in, rounded to half a degree, and handed over as data (`svg().data`), since gpui turns a picture only after it is rasterized and a line turned that way blurs; each tilt is rasterized once and kept by its text's hash. It answers the pointer on a spring (`widgets::Fig`, emaki's `HomeFig`, with a third value for how near the pointer is): the notebook tilts and lifts toward it, the pen comes to the page and writes the bright line as far as the pointer has come across, then goes back to lie by the stone with the line whole, and the window asks for a frame while the spring moves. Under it the greeting by the hour and the account's first name (`greeting`, `sys::user_first_name`), in the note's face so the page and the note agree, and then what can be done next on pills with their keys at the right: New Note, New Folder, Reopen Closed Tab while there is one, Open Vault…. Each page fades and rises in (`page_in`) when it arrives.

## Menus

A right click opens a menu of the app's own (`menu.rs`, `Menus`), one card for every menu here and in the settings window, after emaki's: a card at the pointer kept inside the window, over a clear sheet that a click, a right click or Esc puts away, in over `MENU_IN` and out over `MENU_OUT`. It stands over everything, the search palette and the sheets too. A row is 30 tall with a 15 icon, a little tighter at the left because an icon's drawing stops short of its box, and the card is as wide as its longest row. The order and the icons are in `docs/design.md`, Menus.

| Right click on | The menu |
|---|---|
| A note, in the tree or on its tab (`entry_menu`, one menu wherever) | Rename · Copy Path, Copy Relative Path · Open (unless it shows), Reveal · Close Tab, Close Other Tabs (with a tab) · Move to Trash |
| A folder in the tree | Rename · New Note, New Folder · Copy Path, Copy Relative Path · Open in Finder · Move to Trash |
| The tree's empty room (`show_vault_room_menu`) | New Note, New Folder · Copy Path · Open in Finder · Collapse All Folders |
| The vault's name, by either button (`show_vault_menu`) | New Vault…, Open Vault…, Reveal · Close Vault |
| A folder's handle on the tabs' row (`show_pill_menu`) | Copy Path, Copy Relative Path · Open in Finder · Close Tabs |
| The path (`show_path_menu`) | Copy Path, Copy Relative Path (not for the vault) · Reveal or Open in Finder |
| A note's words or the page round them (`canvas_menu`) | Cut, Copy, Paste · Select All; Read mode and a locked note leave out Cut and Paste |
| A link in the note | Open Link or Open Note · Copy Link, Copy Text, Copy Markdown |
| Any text field: the name over a note, find, search, a sheet's, the settings' (`input_menu`) | Cut, Copy, Paste · Select All |
| A note found in the search (`show_found_menu`) | Copy Path, Copy Relative Path · Open, Reveal |
| A vault on the landing page (`show_recent_menu`) | Copy Path · Open, Open in Finder |

Cut and Copy show only with a selection and Paste only with something on the clipboard, and the line under them goes when none do. The window makes every menu, the note's too: the editor says where and what it was on (`EditorEvent::Menu`). A text's choice is sent to the text it was opened on (`menu::do_edit`, `menu_focus`), which takes the keyboard only then: a right click on a link or in the margin moves nothing, or the marks on the caret's line would wake. A field calls its handler from inside its own update, where it cannot be read, so its menu is made a moment later (`window.defer` in `input_menu`); reading it there aborts the app. A press in an edge fade opens nothing, as it does nothing else there. Not offered, though emaki's files offer them: Cut, Copy, Paste and Duplicate of a file, which need a clipboard of files.

## The sheets

`render_sheet` draws one: a card over a scrim with a title, what it asks, its pills and a line of keys; Esc or a press off the card lets it go, and the card occludes, so a press in it let go outside does not close it. Each sheet's name is in the toolkit's `Input` (`rename_input`, `vault_input`, each made with the window, since an input watches the window it was made in), and ↩ keeps it through the input's `PressEnter`. The rename sheet (`render_rename`) and the new-vault sheet (`render_new_vault`) are the two; one is up at a time. After a sheet the keyboard goes back to the editor when a note is open, else to the window.

## The settings

`settings.rs`, the studio's window: a rail of three sections, the page at the right, drawn from the main view's state so a change shows in both windows. Appearance has the appearance and the accent, and the language at the right of its title. Text is two pages, chosen at the right of its title (`settings_page`): Fonts, the note's face as serifs over sans serifs, code's face and the Chinese face, each on a tile drawn in itself (`fonts_rows`, emaki's Text page), with a field under each card for a font installed on the Mac (`font_inputs`, made with the settings window and listened to for a change; a tile chosen clears the field over it); and Size (`size_rows`), a preset for both places at once (Small, Medium, Large, Custom: `EditorConfig::text_size`, `TextSizes`) with each place's size under it on a stepper, which only Custom moves, and a button back to Medium's beside a size that left it, then Readable line length. Custom's own sizes are kept while a preset is chosen (`EditorConfig::sizes`). About has the title card, Alkaline Software presents with the studio linked, and the updates. A change to a face or a size reaches every editor through `Shell::push_look`.

## What the window remembers

`ui_state.rs`, `~/.onyx/state/ui.json`: the bounds (from `window_bounds()`, never `bounds()`), whether the sidebar is open and how wide, the settings' section, the vault, the note, the mode, the notes shown wide, the recent vaults, the folded folders. Written when any of it changes (the bounds at most every two seconds), at quit, and when the close button closes the window. The writing is a thread's own (`UiState::save_later`, `Shell::save_ui`), the saves in the order asked: `write_atomic` flushes the file to the disk, some 5 ms on an SSD, and a frame is not to wait on that for a tab moved mid-drag or a folder folded. What was last asked is kept and is what `UiState::load` gives, so a state read, changed and written again never misses one still on its way. The window's close (`Shell::save_ui_now`) and the app's quit (`UiState::flush`) wait for the disk, since on Windows and Linux the close ends the app.

## Probing

`ONYX_VAULT=<folder>` opens that vault instead of the remembered one, `ONYX_NOTE=<file>` that note; `ONYX_GO` steps: `note` (the first note), `notes` (the first three, as tabs), `close` (⌘W), `sidebar`, `menu` (the first note's menu), `rename` (its rename sheet), `vault` (the new-vault sheet), `live`, `source`, `reading`, `end`. With `HOME` pointed at a scratch folder the sheet finds no iCloud Drive and makes the vault in that folder's `Documents`, so a probe can press ↩ without touching the person's iCloud. `ONYX_SETTINGS=text` opens the settings on that section (`docs/probing.md`).
